# Folio — личный планировщик для iPhone

Приложение-сайт (PWA) для одного человека, только для iPhone 17 Pro Max. Ставится на экран «Домой» и открывается как обычное приложение. Все данные хранятся на телефоне: своего сервера и аккаунтов нет.

- Адрес: https://egorpido.github.io/folio/
- Репозиторий: https://github.com/Egorpido/folio (публичный)
- Макет-примерочная, где выбирали оформление: https://claude.ai/artifact/Hc7hdbQftawvS8y9YaXq1J
- Исходный утверждённый план: `~/.claude/plans/luminous-hopping-flask.md`

## Как работать с владельцем

- Владелец не программист и не читает код. Общение на русском, простыми словами.
- Один шаг за раз. После шага: что изменилось и как проверить это на телефоне.
- После каждого рабочего шага делать git-коммит и сообщать об этом.
- Если чего-то не знаешь или не уверен, говорить прямо, не придумывать.
- Перед выбором технологий предлагать 2 варианта и объяснять компромиссы простым языком.
- Лимиты Claude: проверять расход (`get_usage`) до и после каждого шага. Останавливаться на 88% пятичасового лимита и на 85% недельного. Ультракод и пакеты параллельных агентов не использовать.

## Принятые решения

### Технологии
- **Svelte 5 + Vite 8 + TypeScript 6.** Svelte выбран вместо React: приложение легче, быстрее открывается, плавные анимации встроены. TypeScript 6, а не 7: `svelte-check` пока поддерживает только 5–6.
- **Хранилище — IndexedDB через Dexie 4.** localStorage отклонён: он маленький (около 5 МБ) и к нему трудно добавить синхронизацию. База называется `folio`, код — в `src/lib/db/`.
  - **Схема готова к синхронизации.** У каждой записи есть `id` (UUID), `createdAt`, `updatedAt`, `deletedAt` (мягкое удаление, «надгробие») и `rev` (номер версии). Описание — `schema.ts`.
  - **Все изменения идут только через `repo.ts`.** Экраны напрямую в базу не пишут. Каждая запись меняется в одной транзакции с добавлением строки в очередь `changes` (outbox): `{seq, table, id, op, at}`. Поверх неё потом можно добавить синхронизацию, не трогая экраны.
  - **Удаление мягкое:** запись получает `deletedAt` и остаётся в базе. Поэтому удаление можно отменить, а синхронизация узнает, что запись удалили. Запросы обязаны отфильтровывать `deletedAt`.
  - **Даты дел** хранятся строками местной даты `YYYY-MM-DD`, время — `HH:MM`. Так часовые пояса не сдвигают дела.
  - **Новая версия схемы** добавляется через `this.version(N)` в `db.ts`, и сохранённые данные переносятся. Старые версии не удалять.
  - **Таблица `meta`** хранит служебные значения устройства, например `deviceId`. Она не синхронизируется.
  - **Живые запросы** (`liveQuery` из Dexie) лежат в `queries.ts`. В компонентах Svelte они читаются через `$имя` и обновляются сами.
- **Защита данных при запуске** (`src/lib/storage.svelte.ts`):
  - открыть базу; если не вышло — экран ошибки `StorageError` с текстом ошибки;
  - создать `deviceId`;
  - запросить `navigator.storage.persist()`;
  - посчитать занятое место.
  Состояние видно в «Ещё → Данные».
- **Быстрый ввод** (`src/lib/Composer.svelte`).
  - Поле внизу экрана «Сегодня». Enter или кнопка ↑ добавляют дело, поле очищается и остаётся в фокусе, клавиатура не прячется. У кнопки `preventDefault` на `pointerdown`, поэтому она не забирает фокус.
  - Новое дело без даты попадает во «Входящие», в конец списка. Экран прокручивается так, чтобы дело было видно над полем.
  - Черновик сохраняется в `localStorage` (`folio:draft`) на каждую букву, чтобы фоновое обновление приложения не стёрло недописанный текст.
- **Клавиатура iPhone** не сжимает страницу, а ложится поверх неё. Поэтому нижняя панель (`.dock` в `App.svelte`) поднимается на высоту клавиатуры по `visualViewport` (`src/lib/viewport.svelte.ts`). Поле ввода встаёт над клавиатурой, а вкладки остаются под ней. Прокрутка списка при открытой клавиатуре её прячет. **На реальном iPhone это проверяет владелец:** в браузере на компьютере клавиатуры нет.
- **Нижняя панель** — одна фиксированная колонка: плашка обновления → поле ввода (только на «Сегодня») → вкладки. Высота панели измеряется, и под неё оставляется отступ у содержимого.
- **Дата «сегодня»** — `clock.today` (`src/lib/clock.svelte.ts`). Она сама меняется в полночь и при возвращении в приложение. Раскладка дел по разделам — чистая функция `groupForToday` (`src/lib/tasks.ts`) с тестами.
- **Тесты:** Vitest + fake-indexeddb (`npm test`). Проверяют слой хранения: очередь изменений, версии, мягкое удаление. В GitHub Actions тесты прогоняются перед каждой публикацией, и при ошибке публикации не будет.
- **Офлайн и установка — vite-plugin-pwa** (`generateSW`). Всё приложение целиком сохраняется на телефоне (precache), поэтому открывается без интернета.
- **Обновления не перебивают работу** (`registerType: 'prompt'`). Новая версия применяется сама, когда приложение уходит в фон. Пока оно открыто, внизу показывается плашка «Есть новая версия · Обновить». При возврате из фона приложение само проверяет обновления: iPhone не перезапускает его. Код — `src/lib/pwa.svelte.ts`.
- **Шрифт заголовков Playfair Display** лежит внутри приложения (`@fontsource/playfair-display`), а не загружается с Google: так он работает без интернета.
- **Выбор темы хранится в `localStorage`** (ключ `folio:theme`), а не в базе дел. Это удобство одного устройства. Скрипт в `index.html` применяет тему до отрисовки, чтобы экран не мигал. Цвет строки состояния (`theme-color`) подстраивается под тему.
- **Иконка:** исходник `public/icon.svg` — лист с золотым уголком, одна строка зачёркнута. PNG-иконки генерируются командой `npx pwa-assets-generator` (настройки в `pwa-assets.config.ts`) и лежат в `public/`. Если поменять иконку, на телефоне приложение придётся переустановить.

### Хостинг
- **GitHub Pages**, публикация через GitHub Actions (`.github/workflows/deploy.yml`) при каждом push в `main`. Cloudflare отклонён: в России его замедляют.
- **Публично видно:** код приложения, история изменений, логин `Egorpido` (он же в адресе сайта).
- **Не публично:** дела и все данные. Они только на телефоне.
- **Почта в коммитах скрыта:** в репозитории настроен noreply-адрес GitHub (см. раздел Git).

### Дизайн (выбрано на шаге 1)
- Название **Folio**.
- Палитра **«Полночь»**: тёмно-синий + золото. Тема по умолчанию как в системе iPhone, плюс ручной переключатель.
- Заголовки — **Playfair Display 600**, текст — системный шрифт iPhone.
- **Неоклассические акценты включены:** золотистая черта под датой, подписи разделов прописными с разрядкой, золотые точки у проектов. Это отдельные детали, а не стиль всего подряд.
- Все цвета и шрифты заданы токенами в `src/styles/tokens.css`. Литеральные цвета в компонентах не используем.

### Поведение (из опроса владельца)
- **Стартовый экран:** «Сегодня» и «Входящие» вместе. Внизу панель вкладок: Сегодня, Проекты, Привычки, Ещё. Строки средней высоты. Всё важное — в зоне большого пальца.
- **Быстрый ввод:** поле внизу экрана. Enter — дело добавлено, поле остаётся активным.
  - Умный разбор без ИИ: «завтра 18:00», дни недели, `!!!`/`!!`/`!` для важности, `#проект`.
  - Кнопка ✨ отдаёт «поток мыслей» ИИ. ИИ возвращает список дел, владелец проверяет его и нажимает «Добавить всё».
  - Голос — через кнопку диктовки на клавиатуре iPhone.
- **Отметка «готово»:** нажатие на дело. Кружок заполняется, текст перечёркивается неспешной золотистой линией (вариант C: 2px, 720 мс) и становится полупрозрачным. Дело висит 2,6 с и плавно уходит в «Выполнено».
- **Отмена:** плашка внизу с обратным отсчётом 5 с, как в Telegram. Ещё можно вернуть дело из раздела «Выполнено».
- **Свайпы:** вправо — на завтра, влево — удалить (тоже с отменой).
- **Важность:** цвет кружка в 4 уровня — срочно, важно, можно позже, без отметки.
- **Подзадачи:** счётчик «2 из 5» под делом.
- **Просроченное:** видно отдельным блоком. Если с ним ничего не сделали, оно само переносится на следующий день. Просрочка дедлайна остаётся заметной.
- **Привычки:** серии и ощущение «я молодец, уже месяц двигаюсь». Конкретный вид покажем вариантами, когда дойдём.
- **Резервная копия:** напоминание раз в неделю.
- **Напоминания v1:** через «Быстрые команды» → системные «Напоминания». Настоящие push-уведомления — позже и по желанию: для них нужен маленький сервер.

### Ограничения iOS (проверено поиском 2026-10-05)
- У приложения с экрана «Домой» своё хранилище, отдельное от Safari. Правило «7 дней» к нему не применяется, пока приложением пользуются.
- `navigator.storage.persist()` в iOS 17+ защищает от авто-очистки. От удаления иконки он не спасает: данные, скорее всего, удаляются вместе с ней. Поэтому экспорт и импорт обязательны.
- Нужен `display: standalone`. Если в iOS 26 выключить «Открыть как веб-приложение», получится обычная закладка Safari. Это надо распознавать и предупреждать.
- Экспорт — только через `navigator.share({ files })` («Сохранить в Файлы»). `<a download>` в режиме приложения сломан.
- Вибрации нет: `navigator.vibrate` на iOS не работает, обходной путь закрыт в iOS 26.5.
- Клавиатура не открывается сама при запуске, только по нажатию на поле.
- Встроенное распознавание речи (Web Speech) в приложении с экрана «Домой» не работает.
- Уведомлений в заданное время без сервера нет: Notification Triggers и Periodic Background Sync не поддерживаются.
- **ИИ-ввод:** OpenRouter с мая 2026 не принимает оплату из России, у DeepSeek напрямую нужна иностранная карта. У владельца российские карты (возможно, есть гонконгская), идеально СБП. Перед шагом 9 исследовать российских посредников: оплата, вызовы прямо из браузера (CORS), цена, приватность.

## Устройство проекта

- `index.html` — страница-оболочка: иконки, мета-теги для iPhone, ранняя тема.
- `src/main.ts` — точка входа: шрифт, стили, тема, запуск приложения и обновлений.
- `src/App.svelte` — оболочка: текущий экран + нижняя панель вкладок + плашка обновления.
- `src/screens/` — экраны вкладок: `TodayScreen` (Сегодня + Входящие), `ProjectsScreen`, `HabitsScreen` (пока заглушки), `MoreScreen` (тема, данные, версия, режим, офлайн).
- `src/lib/db/` — хранилище:
  - `schema.ts` — типы записей;
  - `db.ts` — база Dexie и версии схемы;
  - `repo.ts` — все изменения;
  - `queries.ts` — живые запросы;
  - `repo.test.ts` — тесты.
- `src/lib/storage.svelte.ts` — открытие базы, защита от очистки, занятое место. `src/lib/StorageError.svelte` — экран, если база не открылась.
- `src/lib/` — общие части:
  - `TabBar`, `ScreenHeader` (крупный заголовок + дата + золотая черта), `InstallHint` (подсказка по установке, видна только в Safari), `UpdateBanner`;
  - `Composer` — поле быстрого ввода; `TaskRow` — строка дела;
  - `theme.svelte.ts` — тема;
  - `pwa.svelte.ts` — офлайн и обновления;
  - `clock.svelte.ts` — сегодняшняя дата;
  - `ui.svelte.ts` — общее состояние интерфейса;
  - `viewport.svelte.ts` — высота клавиатуры;
  - `reveal.ts` — прокрутка к элементу над панелью;
  - `dates.ts` — даты (ключи `YYYY-MM-DD`, подписи по-русски);
  - `tasks.ts` — раскладка дел по разделам;
  - `env.ts` — режим приложения, время сборки;
  - `types.ts`.
  Рядом лежат тесты `*.test.ts`.
- `src/styles/tokens.css` — цвета, шрифты, параметры зачёркивания, размеры. `src/styles/base.css` — базовые стили и общие классы (`.group-label`, `.group-empty`, `.placeholder`).
- `public/` — иконки и их исходник `icon.svg`.
- `vite.config.ts` — сборка: `base: '/folio/'` под адрес на GitHub Pages, manifest и офлайн (VitePWA), `__BUILD_TIME__` — время сборки.
- `.github/workflows/deploy.yml` — проверка, сборка и публикация.

Время сборки показывается в «Ещё → Версия». По нему владелец проверяет на телефоне, что новая версия дошла.

**Локальный просмотр в панели браузера:** конфигурация `folio-preview` лежит в `../.claude/launch.json` (корень сессии, вне репозитория). Она запускает `npm run preview` на порту 4173, адрес — http://localhost:4173/folio/. Предварительно нужен `npm run build`.

## Команды

- `npm run dev` — локальный запуск: http://localhost:5173/folio/
- `npm run check` — проверка типов и Svelte.
- `npm test` — тесты (Vitest).
- `npm run build` — сборка в `dist/`.
- **Публикация:** `git push` в `main`, через 1–2 минуты сайт обновлён. Статус: `gh run list`.
